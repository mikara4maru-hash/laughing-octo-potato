## 0. 国語を「個別最適な演習」にするための考え方

国語は、自動採点しやすい分野としにくい分野の差が大きい教科です。そこで分野ごとに扱いを分けます。

| 分野 | 主な中身 | 自動採点 | 扱い |
|---|---|---|---|
| 漢字 | 読み、書き（同音・同訓異字の使い分け） | しやすい | 個別最適な演習の中心 |
| 語句・語彙 | 慣用句、ことわざ、四字熟語、類義語・対義語、敬語 | しやすい | 個別最適な演習の中心 |
| 文法 | 文節・単語、品詞、用言の活用、助詞・助動詞 | しやすい | 個別最適な演習の中心。学年をまたぐ前提関係がはっきりしている |
| 古典 | 歴史的仮名遣い、古語の意味、係り結び、漢文の訓読 | しやすい | 個別最適な演習の中心 |
| 読解 | 説明的文章、文学的文章（指示語、接続語、要旨、心情など） | 選択式・抜き出しなら可 | 1本文に設問をまとめた「本文セット」で出す |
| 書くこと | 意見文、要約、振り返り | できない | 採点はしない。記録して教師が読む（見取りの材料） |

- 漢字の「書き」は、Chromebookのかな漢字変換で答えが出てしまうため、選択式（同音異字から選ぶ）で出す
- 読解の本文は、教科書の文章は著作権の関係で使わず、自作の文章か著作権の切れた文章（青空文庫など）を使う

## 1. 学習の流れ

### 生徒の1回の演習（10〜15分）

1. **始める**：教師の指定、「おすすめ」、分野を選んでの練習のどれかで始める
2. **解く**：1問ずつ表示する。解答形式は選択、短答入力（読みのひらがな、抜き出し）、並べ替えの3種類
   - 読解は左に本文、右に設問を並べ、1本文の設問（3〜5問）を続けて解く
3. **自動採点**：その場で正誤を返す
   - 不正解なら、ヒント1 → ヒント2 → 解説の順に段階的に開ける。答え直しは2回まで
   - よくある誤答には専用のメッセージを返す（例：「ゐ」を「い」に直していない）
4. **自信度**：「自信あり／なんとなく／わからない」を1タップで選ぶ
5. **習熟度の更新と次の問題の選択**（下の出題ルール）
6. **終わる**：10問（読解は1本文）か「やめる」で終了。今日の結果を表示し、一言の振り返りを書く

### 出題ルール（試作版）

- 問題は「スキル」（例：中2 文法「用言の活用の種類」）にひも付ける。スキルには、下の学年を含む前提スキルがある（例：中1「文節と単語」→ 中1「品詞の分類」→ 中2「用言の活用」→ 中3「助動詞の意味」）
- 生徒×スキルごとに **習熟度 0〜100** を持つ
  - 正解（ヒントなし）：+15 × 難易度係数（基本0.8／標準1.0／発展1.2）
  - 正解（ヒントあり）：+5
  - 不正解：-10
  - 80以上で「習熟」
- 次の問題の選び方
  1. 同じスキルで2問続けて不正解 → **前提スキル**の問題に戻る（下の学年に戻ることもある）
  2. 対象スキル（教師の指定、なければ自分の学年のスキル）のうち、未習熟で習熟度が最も低いものを選ぶ
  3. 難易度は習熟度に合わせる：0〜39は基本、40〜69は標準、70以上は発展
  4. 習熟済みのスキルは3日後・7日後に **復習1問** を混ぜる
  5. 直近に出した問題は出さない
- 読解は本文セット単位で出す。設問ごとに「指示語」「接続語」「要旨」「心情」などのスキルを付け、正誤はスキルごとの習熟度に入れる。次の本文は、苦手なスキルの設問が多いものを選ぶ

### 教師の流れ

- **授業前**：学年・分野・スキルを選んでクラスに「演習の指定」を出す（期限は任意）
- **授業中**：クラスの習熟ヒートマップを見て、つまずきが多いスキルを全体で扱い、止まっている生徒に声をかける
- **授業後・週末**：生徒ごとの履歴、自信度と正誤のずれ、振り返りを読み、次の授業や個別の声かけ、懇談（見取りノート）に活かす

## 3. 記録するデータ

| データ | 主な項目 |
|---|---|
| Skill（スキル） | id、学年、分野（漢字／語句／文法／古典／読解）、名前、前提スキルid[]、並び順 |
| Passage（本文） | id、学年、種類（説明的／文学的／古文／漢文）、題名、本文、出典 |
| Problem（問題） | id、skillId、passageId（読解のみ）、難易度（1〜3）、問題文、解答形式（選択／短答／並べ替え）、選択肢、正答（表記ゆれを含めて複数可）、ヒント[2]、解説、よくある誤答と対応するメッセージ |
| Student（生徒） | id、表示名、学年、組、出席番号 |
| Attempt（解答記録） | studentId、problemId、回答、正誤、何回目の回答か、使ったヒント数、所要秒数、自信度、日時 |
| Mastery（習熟度） | studentId、skillId、値（0〜100）、習熟した日、次の復習日 |
| Session（演習回） | studentId、開始・終了日時、問題数、正答数、振り返り |
| Assignment（演習の指定） | 学年、分野、skillId[]、期限、作成日時 |

- 習熟度はAttemptから再計算できるため、正しい記録の元はAttemptとする
- 短答の採点は、前後の空白・全角半角・ひらがなとカタカナの違いをそろえてから正答と比べる
- 自信度と正誤の組み合わせ（「自信ありで不正解」など）は、教師の見取りの手がかりとして個別ページに出す

## 4. 画面と操作の概要

1つのHTMLの中で、画面上部のタブで「生徒」と「教師」を切り替える。Chromebookの横長画面に合わせ、キーボードだけでも操作できるようにする（Enterで答える、1〜4キーで選択肢を選ぶ）。

**生徒側**

1. **ホーム**：教師からの指定、「おすすめで始める」ボタン、分野を選んで練習、習熟度マップ（行が分野、列が学年のマス目）
2. **演習**：問題文、解答欄、「答える」ボタン、ヒントボタン（不正解後に有効）、進み具合（3/10）。読解は左に本文（縦書き）、右に設問。正誤は丸・バツと短いメッセージで返す。解答後に自信度の3ボタンを出す
3. **結果**：正答数、上がったスキル、次の復習予定、振り返りの入力欄、「データを書き出す」ボタン

**教師側**

1. **クラス**：ヒートマップ（行が生徒、列がスキル。分野・学年で絞り込み）、つまずきスキル上位3件、「デモデータを読み込む」「生徒データを読み込む」ボタン
2. **生徒の個別ページ**：習熟度の推移、最近の解答（誤答の中身つき）、自信度と正誤のずれ、振り返りの一覧
3. **演習の指定**：学年・分野・スキルにチェックを入れ、期限を選んで出す（試作では同じ端末の生徒側に反映）

## 5. 初期試作で実装する範囲

**作るもの**

- HTML 1ファイル（見取りノートと同じトーンのデザイン）。データはlocalStorage
- 問題データ（中1〜中3）
  - 漢字・語句・文法・古典：各学年・各分野にスキル2つずつ、計24スキル。スキルごとに基本・標準・発展を1問以上、計約90問
  - 読解：各学年1本文（説明的文章か文学的文章、自作か著作権の切れた文章）、1本文につき設問4問、計3本文
  - 文法は学年をまたぐ前提関係を1本通す（文節と単語 → 品詞の分類 → 用言の活用 → 助動詞の意味）
- 上の出題ルール、習熟度計算、段階ヒント、よくある誤答へのメッセージ、自信度、振り返り
- 生徒画面3つ（読解の左右レイアウトを含む）、教師画面3つ
- 「生徒として試す」と、30人分のデモデータ
- 生徒データのJSON書き出しと、教師側での複数ファイル読み込み・集計

**作らないもの**

- ログイン、サーバー、端末間の自動同期
- 書くことの提出、記述式の採点、AIによる問題生成や採点
- 画面からの問題作成（問題はJSONで用意する）
- 複数クラス、保護者向け画面
- 見取りノートとの連携（試作の評価後に検討）

**先生が触って確かめること**

- 出題ルールで「ちょうどよい難しさ」になるか（わざと間違えると前提スキルに戻るか、正答率60〜80%に収まりそうか）
- ヒートマップとつまずき上位を見て、授業中の次の一手を決められるか
- 1回を10分程度で終えられるか、Chromebookで入力しやすいか
- 問題の量と質（学年ごとの難しさ、ヒントと解説の書き方）が授業で使える水準か

## ゴール1：問題データ

- 問題データ: `data/kanji-g3.json`、先生確認用の一覧: `docs/kanji-g3-questions.md`
- 93問（読み47問、書き46問）。範囲7つ × 難しさ3段階（基本・標準・発展）
  - 読み：音読みの熟語25、訓読み・送り仮名12、特別な読み（熟字訓）10
  - 書き：同音異義語14、同訓異字12、まちがえやすい熟語12、四字熟語8
- 決めたこと
  - 読みはひらがなで入力。ひらがな／カタカナ・全角／半角・空白の違いはそろえてから採点し、読みが複数ある語（施行、免れる）はどちらも正解にする
  - 書きは選択式（Chromebookのかな漢字変換で答えが出てしまうため）。誤りの選択肢は同音・同訓の語か、形の似た字にする
  - 例文はすべて自作（教科書の文は使わない）
- 未確定：教科書の単元・学期との対応づけ、問題の量（試行前に先生が一覧を確認し、追加・修正する）

## ゴール2・3：試作品

- `prototype/kanji-note-g3.html`（ブラウザで開くだけで動く1ファイル。`python3 tools/build.py` で `src/app.html` と問題データから作る）
- 生徒側
  - 初回に組・番号・名前を登録
  - 範囲（7つ）・難しさ・問題数（5/10/20/すべて）・出題の順番（おすすめ／ランダム）を選んで開始。おすすめは「苦手 → 未学習 → あと一歩 → 習得」の順に優先
  - 1問ごとにその場で ○×・正答・解説を表示。キーボードだけで操作できる（Enterで解答・次へ、数字キーで選択）
  - 結果：得点（100点満点）、正解数、学習時間、解いた問題の一覧、ふりかえり、まちがえた問題だけもう一度
  - 学習の記録：取り組んだ問題数、正答率、学習時間の合計、習得した漢字数、学習回数、正答率の推移グラフ、範囲ごとの習得状況、苦手な漢字（解説つき）と復習、学習の履歴、成長（はじめの3回と最近の3回の正答率の比較）
- 習得状況の決め方：問題ごとに、直近2回連続正解＝習得／直近が正解＝あと一歩／直近が不正解＝苦手／未解答＝未学習
- 学習時間：1問の表示から解答までの時間の合計。放置を数えないよう1問3分で打ち切る
- データは端末内（localStorage）に保存。サーバーは使わない

## ゴール4に向けて組み込んだもの（試行の準備）

- 生徒：「記録を書き出す」でJSONファイルを保存し、先生に提出する
- 先生用タブ：記録ファイルをまとめて読み込み、利用状況（人数・問題数・正答率・学習時間・最終利用）、まちがいの多い問題と多かった誤答、範囲ごとの正答率、生徒のふりかえり・感想の一覧を表示。先生の気づきを日付つきで記録。集計と気づきをCSVで保存
- 先生だけで画面を確かめるための「デモデータ（架空の30人分）」

### 試行の進め方（案）

1. 先生がデモデータと「生徒として」の操作で一通り触り、問題一覧を確認・修正する
2. 試作品のHTMLを生徒のChromebookに配る（Google ドライブやClassroomで共有し、各自の端末でブラウザで開く）
3. 1〜2週間、授業の最初の10分や家庭学習で使ってもらう
4. 期間の終わりに生徒が「記録を書き出す」→ Classroom等で提出 → 先生用タブで読み込んで集計
5. 感想は毎回の「ふりかえり」に加え、最後に短いアンケート（使いやすさ・続けたいか・分かりやすかった点・困った点）をとる

注意：記録は端末のブラウザの中だけにあるため、ブラウザのデータを消したり別の端末で開くと記録が引き継がれない。試行中は同じ端末・同じブラウザで開くよう伝える。
